## 本次发现的同步差异

桌面 `服务端/攀搭改动代码/` 中的存储与线路工具副本落后于实际运行目录，并缺少按键消息处理与注册文件。此次独立快照使用实际运行目录中的源码。

设备源码不在桌面项目目录，而在 `~/panda-firmware/xiaozhi-esp32/`：包含已提交的按键 / 长按 / 离线补发，以及尚未提交的改按和显示改动。快照同时收录两者。

原进度文档主要记录到线路登记；不能用它单独判断按键和屏幕实现进度。代码存在也不代表全部能力已经连设备实测。

## `panda` 消息示例

```json
{"type":"panda","event":"attempt","result":"fail","id":"boot-1"}
```

窗口内改按使用相同 ID，并附带 `"fix": true`。服务端以 `attempt_ack` 返回结果、线路、次数和显示文案。线路登记通过 `{"type":"panda","event":"route","route":"黄色V3"}` 推送设备。

3 秒窗口由固件管理；服务端处理 `fix` 更新与去重，不能把服务端更新测试等同于物理按键计时验证。
